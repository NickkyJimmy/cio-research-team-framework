## Target Audience Selection Framework

Use this reference to select the right audience based on three inputs from the brief:

1. Objective type
2. Timeframe pressure
3. Brief completeness and confidence

Do not pick segments by habit. Pick segments that can answer the decision.

## Step 1 - Read Brief Constraints First

Extract these fields before selecting audience:

- Core objective and sub-objectives
- Decision owner + decision date
- Deadline/time available for fieldwork
- Method hint (qual/quant/mixed)
- Data confidence (clear metrics vs unclear assumptions)
- Budget constraint (affects number of segments feasible)

If any of these are missing, flag and ask before locking segments.

## Step 2 - Objective-to-Audience Routing

### Objective: Product health / benchmark / prevalence

- Primary: Mass or Active users (e.g., Monthly Active Users, Active 30-day cohort)
- Secondary: 1 lifecycle segment for interpretation
- Why: need broad representativeness

### Objective: Funnel optimization / onboarding / conversion

- Primary: Lifecycle segments (Non-User, New User, Current User)
- Secondary: Frequency segment (Light/Heavy) for friction contrast
- Why: decision is stage-specific, not whole-market

### Objective: Churn reduction / retention recovery

- Primary: Churn User + Reactivated User
- Secondary: Current User as control
- Why: captures both exit reasons and recovery signals

### Objective: Advanced feature optimization / depth usage

- Primary: Medium User + Heavy/Power User
- Secondary: Light User for accessibility gap
- Why: need depth and adoption barrier contrast

### Objective: Campaign/message evaluation

- Primary: target campaign audience from brief
- Secondary: non-exposed or low-exposure comparison group
- Why: need message impact and lift interpretation

### Objective: Market entry / new product

- Primary: Potential users (non-users with need indicators)
- Secondary: Current users of competitor/alternative solutions
- Why: need demand signals and switching triggers

## Step 3 - Timeframe and Feasibility Rules

### Tight timeline (<= 2 weeks)

- Limit to 1 primary + 1 secondary segment
- Prioritize easiest-to-recruit high-signal segments
- Avoid fragmented quota cells

### Moderate timeline (3-4 weeks)

- Use up to 3 meaningful segments
- Include one contrast segment for decision confidence

### Flexible timeline (>= 5 weeks)

- Use full segmentation (lifecycle + frequency) if objective requires deeper diagnosis

If requested segmentation is too wide for timeline or budget, propose a phased plan:

- Phase A: decision-critical segments now
- Phase B: extended segments later

## Step 4 - Brief Quality Rules

### Brief quality high (clear KPI + explicit decision)

- Select narrower segments tightly aligned to decision

### Brief quality medium (objective clear, KPI weak)

- Add one validation segment to reduce bias risk

### Brief quality low (vague objective, unclear decision)

- Do not over-segment
- Start with discovery-oriented core segments
- Mark audience selection as provisional

## Audience Layer Library

### Layer 1: Mass (Scale and Breadth)

- Mass: full potential/current user base for broad incidence
- Active cohorts (e.g., A30/A60): active users within defined recency windows for retention-quality view

Use when objective requires macro health or benchmark tracking.

### Layer 2: Product Lifecycle

- Non-User: barriers and awareness gaps
- New User (e.g., <7d or <30d depending on product): onboarding and aha-moment quality
- Churn User (e.g., >30d inactive): drop-off reasons
- Reactivated User: return triggers and value signals
- Current User (DAU/WAU/MAU): in-product experience quality

Use when objective is funnel, adoption, churn, or lifecycle optimization. Adapt time thresholds to the specific product's usage patterns.

### Layer 3: Frequency / Engagement Depth

- Light User: low engagement, friction discovery
- Medium User: steady behavior baseline
- Heavy/Power User: advanced needs and depth usage

Use when objective focuses on depth, complexity, and feature intensity. Define frequency thresholds based on the product's usage distribution.
